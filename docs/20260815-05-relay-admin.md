# 20260815-05 · 中继管理界面

## 背景

中继已有账号注册表（token → 设备）与管理 CLI，但操作要 SSH 上服务器敲命令，
无法直观查看「哪个账号、哪些设备、在线状态」等。需要一个**管理 Web 界面**：
管理员密码登录后，查看/增删账号令牌、查看各账号及其设备的在线状态、删除设备等。

## 设计

### 1. 入口与路由

管理界面与 Web 客户端共用同一个静态托管（`RELAY_STATIC_DIR`），通过路径区分：

```
/admin         → 管理界面（独立 Vite 应用，单独构建）
/              → 远程客户端（现有 apps/remote）
```

`handleStatic` 增加路由：`/admin` 前缀 → 管理界面 dist 目录（`RELAY_ADMIN_STATIC_DIR`），
其余 → 现有客户端。管理界面构建产物单独放一个目录，由部署脚本一起上传。

### 2. 服务端 HTTP API（在 RelayServer 上加）

不在 `handleStatic` 里塞逻辑，抽一个 `handleAdminApi`。管理 API 挂 `/api/admin/*`，
**只对 /admin 来源开放**（校验 Origin/Referer 含管理界面路径，防止跨站）。

鉴权采用**管理员密码 + 会话 token**：

| 端点 | 说明 |
| --- | --- |
| `POST /api/admin/login` | body `{ password }`，校验 `RELAY_ADMIN_PASSWORD`，成功签发会话 token |
| `GET /api/admin/sessions` | 校验会话 → 返回会话列表（无敏感信息） |
| `GET /api/admin/accounts` | 校验会话 → `[{ token, note, devices: [{ device, online }] }]` |
| `POST /api/admin/accounts` | `{ token, note? }` 新增账号 |
| `DELETE /api/admin/accounts/:token` | 删除账号（同时清设备） |
| `DELETE /api/admin/accounts/:token/devices/:device` | 删除单个设备 |
| `POST /api/admin/logout` | 注销会话 |

会话实现：无第三方依赖，内存 `Map<sessionId, expiresAt>`，签发随机 token，
设置 `HttpOnly` cookie（`workbench_admin`）。会话 24h 过期。

管理 API 复用 relay 的 `AccountRegistry`（`registry.upsertAccount` 等），
与 CLI 共用同一 `accounts.json`——热重载照常生效，管理界面的增删立即同步到运行中继。

### 3. 管理界面（新应用 apps/admin）

独立 Vite + React 应用（复用 `@/lib/connection` 的思路但更简单）：
- 登录页：输入管理员密码 → `POST /api/admin/login`
- 仪表盘：
  - 账号列表（token、备注、设备数）
  - 每账号展开设备列表：deviceId + **在线/离线**状态（复用 `RelayDeviceInfo` 语义）
  - 新增账号（token + 备注）、删除账号、删除设备
- 顶部：中继状态（uptime 可选）+ 退出登录

构建：`apps/admin` 独立 `vite build`，产物 `dist/` → 部署上传到 `$REMOTE_DIR/admin-web`。

### 4. 部署 & 配置

- 新增环境变量 `RELAY_ADMIN_PASSWORD`（必填才启用管理界面）、`RELAY_ADMIN_STATIC_DIR`。
- `startRelayFromEnv` / `RelayServerOptions` 增加这两项。
- `scripts/deploy-relay.sh`：构建并上传 `apps/admin`，写 `RELAY_ADMIN_PASSWORD`/`RELAY_ADMIN_STATIC_DIR`。

### 5. 安全

- 管理 API 仅本机 + 会话 cookie 双因素（无 cookie 一律 401）。
- 会话 token 内存存储、24h 过期；注销即失效。
- 管理 API **不**返回设备会话内容（无请求/响应体），只返回账号与设备元数据、在线状态。
- Cookie 设 `SameSite=Strict`、`HttpOnly`；管理界面 https 部署时 Cookie 加 `Secure`（wss 环境下才附加）。
