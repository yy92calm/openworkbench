# Workbench 沙盒机制实现方案

版本：v0.2（实施记录）
日期：2026-09-01（评审稿）；2026-09-03（实施状态记录）
状态：核心已实施（代码在工作区，未提交 git）；UI 状态展示于 2026-09-03 补齐

## 一、结论先行

参照 Codex 的三平台沙盒架构，在 Workbench 主进程新增 sandbox 模块，对 sidecar（opencode）与
Python kernel 两条执行链路做 spawn 前包装：macOS 用系统自带 Seatbelt（sandbox-exec 加 SBPL 策略），
Linux 用 bubblewrap 命名空间隔离，Windows 第一阶段降级为审批-only 并明确提示，第二阶段引入受限令牌
原生模块。策略档位与现有 permission 档位联动，打包 profile 锁死上限，用户只能收紧。

不选 Docker 容器方案（桌面用户安装负担重、冷启动慢、与本地 Python/R 环境冲突），不选自研 Rust 沙盒二进制（项目无 Rust 工具链，Codex 的 linux-sandbox 编译产物跨平台维护成本高）。macOS 与 Linux 的 OS 原生包装用纯 TypeScript 即可实现，Codex 已验证此路径可行。

## 三、关键约束

1. sidecar 是 127.0.0.1 HTTP 服务，用 OPENCODE_SERVER_PASSWORD 鉴权（server.ts:50-53，relayHost.ts:252 Basic auth 转发）。沙盒必须放行回环 bind 与 connect，且不能破坏主进程到 sidecar 的 HTTP 与 SSE 链路。
2. sidecar 依赖 XDG 四目录重定向到 userData/runtime（server.ts:59-67），这些路径必须对 sidecar 可写；
   同时它们含 provider 密钥与 profile，必须对"agent 写操作"保护。矛盾点：sidecar 进程本身需要读写
   这些目录，而 agent 的 shell 在 sidecar 内运行，同进程权限无法区分。处理：将 runtime 目录纳入可写根，
   但把密钥文件所在子目录通过保护子路径规则拒绝 shell 写入（macOS deny file-write* 正则，Linux ro-bind）。
   读取侧第一阶段不拦（Codex 的 deny-read 同样是进阶特性）。
3. workspace 目录用户可随时切换（active-workspace.txt），策略必须在每次 spawn 前按当前 workspace 重新生成，不缓存陈旧路径。
4. macOS sandbox-exec 在新系统标记 deprecated 但仍随系统分发，Codex 生产在用；硬编码 /usr/bin/sandbox-exec 路径，不走 PATH。
5. Linux 无系统 bwrap 时降级：策略档位为 read-only 或 workspace-write 且检测失败时，主进程弹一次性告警并在 UI runtime 状态显示"沙盒未生效"，是否阻断执行由打包 profile 决定（新增 sandbox_required 配置键，默认 false）。
6. AppImage 打包不捆绑 bwrap 二进制（静态 bwrap 约 1MB 但需维护上游来源与签名），第一阶段仅探测系统 bwrap。
7. node-pty 终端链路第一阶段不接入沙盒（终端是用户亲手操作，与 agent 自动执行信任级不同），方案内声明边界。
8. 改动不得触碰 relay / client 两个独立项目；sidecar 鉴权链与 WebSocket 转发保持不变。

## 四、策略模型

三档，命名与语义对齐 Codex：

| 档位            | 文件系统                                                                 | 网络               | 适用                                         |
| --------------- | ------------------------------------------------------------------------ | ------------------ | -------------------------------------------- |
| read-only       | workspace 与全部用户目录只读，仅 XDG runtime 可写                        | 回环放行，外联可配 | review 模式默认搭配                          |
| workspace-write | workspace 可写，其余只读；workspace 内 .git、.workbench 子路径二次拒绝写 | 同上               | auto 模式默认搭配                            |
| full-access     | 无限制                                                                   | 无限制             | 仅打包 profile 显式声明时可用，UI 不提供入口 |

新增配置键（进打包 profile，受 patchOverlay 只能收紧策略约束）：

```json
sandbox: { mode: "read-only" | "workspace-write" | "full-access", required: boolean, network: "open" | "loopback-only" }
```

联动规则：permission 与 sandbox 独立生效、取交集。例如 permission bash: ask 且 sandbox workspace-write 时，命令先过审批、再被 OS 沙盒约束，双闸门。

## 五、模块结构

新增 apps/desktop/src/main/sandbox/ 目录，与 server.ts、kernel.ts 平级：

```text
sandbox/
  types.ts        SandboxPolicy 档位类型、SandboxSpawnContext（cwd、workspaceRoots、writableRoots、env）
  manager.ts      平台检测与分发：getPlatformSandbox() 返回 seatbelt | bwrap | unsupported；wrapCommand(ctx, file, args) 统一入口
  seatbelt.ts     macOS：SBPL 模板渲染（策略以 TS 模板字符串内嵌，仿 Codex include_str!）、argv 组装
  bwrap.ts        Linux：系统 bwrap 探测（execFile('bwrap', ['--ro-bind','/','/','/bin/true']) 探活加超时）、argv 组装、WSL1 排除
  policy.ts       路径收集：workspace、XDG runtime、保护子路径清单（.git、.workbench、.sandbox 元数据）、SBPL 与 bwrap 双格式输出
  windows.ts      第一阶段返回 unsupported 并产出提示文案；预留第二阶段受限令牌接口
  sandbox.test.ts 各平台 argv 快照测试与策略渲染单测
```

代码量预估：核心 600 行以内，不含测试。

## 六、接入点

1. sidecar 启动：server.ts:382 的 spawn 调用改为 wrapCommand 后执行。sidecar 被沙包住，意味着 agent 在其内派生的所有 bash 子进程天然继承沙盒约束，一处包装覆盖全链路，这是本方案与 Codex 同构的核心收益。
2. Python kernel：kernel.ts:27-32 同样包装。python 进程与 sidecar 同策略档位。
3. 审批链路不改：permission.asked SSE、InteractionPrompt 三键、replyPermission 原样保留，沙盒在其下游。
4. renderer 加固附带项：windows.ts:50 sandbox: false 改 true 需回归 webview 标签与 FilePreviewInspector，单列为加固清单不在本方案范围强行绑定。
5. UI 展示：runtime 状态区增加当前沙盒档位与生效状态（生效 / 未支持 / 未生效告警），数据来自主进程一次 IPC 查询。

## 七、三平台实现细节

### macOS（首发完整实现）

SBPL 策略骨架（语义仿 Codex seatbelt_base_policy.sbpl）：

```text
(version 1)(deny default)
(allow process-exec* (subpath <sidecar 路径>) (subpath "/bin") (subpath "/usr/bin") (subpath "/sbin"))
(allow file-read* (subpath "/"))
(allow file-write* (subpath <workspace>))
(deny file-write* (regex #"^<workspace>/\.git(/|$)"))
(deny file-write* (regex #"^<workspace>/\.workbench(/|$)"))
(allow file-write* (subpath <xdg-runtime 路径>))
(allow network-bind (local ip "127.0.0.1:*"))
(allow network-outbound)  ; network: open 档
```

要点：可执行范围收敛到系统标准目录加 sidecar 自身加 enrichedPath 里的 conda/pyenv/homebrew 前缀目录（否则 python3 起不来）；deny default 下 sysctl、IPC 类按 Codex base policy 白名单语义补齐，落地时以冒烟脚本逐项验证。

### Linux（首发完整实现）

bwrap argv 骨架：

```text
bwrap --unshare-pid --dev /dev --proc /proc \
  --ro-bind / / \
  --bind <workspace> <workspace> \
  --ro-bind <workspace>/.git <workspace>/.git \
  --ro-bind <workspace>/.workbench <workspace>/.workbench \
  --bind <xdg-runtime> <xdg-runtime> \
  [--unshare-net]  ; network: loopback-only 档第一阶段不做代理桥，直接二选一：open 或断网
  -- <file> <args...>
```

要点：--unshare-user 隐含在 --unshare-pid 链路中，探测脚本须先验证 user namespace 可用（Codex 同款
探活：bwrap --unshare-user --unshare-net --ro-bind / / /bin/true，500ms 超时）；WSL1 直接判
unsupported。network: loopback-only 在 Linux 上无代理桥则无法既断外联又留回环（bwrap unshare-net
是全断），第一阶段该档在 Linux 等价于全断，文档写明；代理桥留待第二阶段评估。

### Windows（分阶段）

第一阶段：manager 返回 unsupported，UI 提示"当前平台依赖审批机制，OS 级沙盒未启用"，sandbox.required 为 true 时阻断 runtime 启动。
第二阶段：新增 node 原生 addon（N-API）封装 CreateRestrictedToken 加空 ACL 写保护，或评估 PowerShell 局部令牌方案，另立方案评审。

## 十、风险与边界

1. SBPL 在不同 macOS 版本语义偶有差异，冒烟脚本须在打包流水线覆盖的最低支持版本上跑通。
2. 沙盒包住 sidecar 后，sidecar 自身的文件操作（profile 部署、会话存储）也受限，XDG 路径必须全部纳入可写根，遗漏会导致启动失败；阶段二联调重点。
3. enrichedPath 注入的第三方目录（conda 等）若含可写位置，进程可执行范围需同步覆盖，否则报 process-exec 被拒，表现为 agent 完全无法跑命令；冒烟脚本第一项即验证。
4. 本方案只约束 agent 自动执行，不约束用户手动终端（node-pty）与用户手动操作，边界在 UI 文案中写明。
5. 密钥读取面第一阶段不拦，恶意命令理论上可读 userData 下的 provider 密钥；缓解依赖审批闸门与 profile 锁定，deny-read 列入第二阶段。
